# Computer Use native RPC incident and preflight

This is the operational contract for the direct Windows Computer Use channel
used by the ROK harness. It is deliberately separate from game policy: a
native-channel failure is an infrastructure blocker and must never be turned
into a guessed UI state or an input attempt.

## Incident: native inventory returned `apps: []`

Observed on 2026-09-19 while `MASS.exe` was running elevated:

- `cua.getState()` returned browsers but an empty native `apps` list.
- Importing `@oai/sky` from the `cua_repl` session failed with
  `Trusted RPC service is not configured: sky`.
- The independent trusted Sky channel was healthy: `sky.list_apps()` returned
  `MASS` / `Rise of Kingdoms`, HWND `15467430`, PID `26328`.
- `codex-computer-use-swift.exe` was running, so this was not a missing binary,
  missing ROK process, UIPI failure, or an admin-elevation problem.

### Root cause

The app-managed `unified-computer-use` launcher had a split configuration:

```text
CUA_REPL_ENABLED_SURFACES=browser
NODE_REPL_TRUSTED_SERVICES={"browser":"@oai/browser-desktop/service"}
```

The general `node_repl` configuration already contained Sky, but that does not
override the plugin's own `.mcp.json`. The CUA child therefore booted in
browser-only mode and could not expose native apps.

### Applied repair

The active launcher cache was changed to:

```text
CUA_REPL_ENABLED_SURFACES=browser,computer
NODE_REPL_TRUSTED_SERVICES={"browser":"@oai/browser-desktop/service","sky":"@oai/sky/service"}
```

The running CUA worker must be restarted after this change; ROK itself does not
need to be restarted. A post-restart `cua.getState()` showing the ROK window is
the acceptance evidence. Until that evidence exists, native input remains
disarmed.

## Non-regression contract

Before any native Computer Use action, the harness/operator must verify all of
the following:

1. `CUA_REPL_ENABLED_SURFACES` contains `computer`.
2. `NODE_REPL_TRUSTED_SERVICES` contains `sky: @oai/sky/service`.
3. `SKY_CUA_NATIVE_PIPE` and `SKY_CUA_NATIVE_PIPE_DIRECTORY` are present.
4. `cua.getState()` returns a non-empty `apps` list and the exact target window
   (for ROK, title `Rise of Kingdoms` and the current HWND) is selected before
   any coordinate or accessibility action.
5. A missing native app, a transport-closed error, or a Sky RPC error is a
   fail-closed infrastructure blocker. Capture-only observation may continue;
   no keyboard/mouse input or mission tick may be sent.

The launcher cache is app-managed and may be regenerated by a Codex update. If
the symptom recurs, compare the two variables above first; do not change ROK's
elevation, install a VM/container, or bypass the native RPC boundary.

### Windows 10 capture note

On this host, Sky native inventory, window binding, accessibility and input
actions worked after the trusted RPC repair, but Sky's screenshot path emitted
`SetIsBorderRequired failed: No such interface supported (0x80004002)`. The
canonical passive evidence path is therefore
`scripts/capture_rok_observation.py` plus `scripts/windows_ocr.ps1`, still bound
to the exact HWND/PID/frame hash. This is a capture-backend limitation, not a
reason to guess coordinates or to treat a stale screenshot as current state.
